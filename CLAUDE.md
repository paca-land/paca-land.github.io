# Working on PaCaLand

Personal landing page for paca.land. See `README.md` for what it is and a file map. These notes cover how the code fits together and the traps already found.

## Ground rules

- **Static, no build step.** Plain ES modules plus an import map. three.js r170 and its add-ons are vendored in `vendor/three`; never load scripts from a CDN (the owner wants no third-party JS). Vendor any new add-on and its imports (check that `from '...'` resolves inside `vendor/`).
- **Deploys** come from pushing `main` (GitHub Pages, custom domain via `CNAME`, which must stay). The owner pushes or approves pushes; don't push unasked.
- **Cache-busting:** GitHub's CDN caches for ~4h. Any change to the site's own files means bumping **every** `?v=N` in `index.html` together (stylesheet, `js/main.js`, all import-map entries for `./js/*.js`). A new module needs an import-map entry.
- **Lands are seeded.** `makeRandom(seed, 'stream')` gives each subsystem its own stream. Any generator change (weights, terrain, extra draws, placement order) reshapes every land. The journal remembers the words where things were found, so changes also move what those links show; freeze or version the generator if that starts to matter.
- **Rarity tables** (`js/rarity.js`) are counted from generated lands. After changing biome weights, landmarks, lakes, rivers or the balloon, recount: generate ~1,600 seeds in the console (in chunks of ~160; each takes ~110 ms), tally landmark and water (`dry` / `lake` / `falls`) per biome, then recompute the score percentiles and tier cut-offs (top 50/20/5/1%).
- **Journal events:** land parts report through `hooks.note(kind)` (`flower`, `tree`, `splash`, `ice`, `landmark`, `duck`, `rabbit`, `deer`, `fish`, `bats`, `fireflies`, and each `CRITTERS` kind in `life.js`: `sheep`, `goat`, `squirrel`, `lizard`, `penguin`, `frog`, `crab`, `snail`, `giraffe`, `panda`); sky sights come from `env.aurora`, `env.meteor`, `env.rainbow` and `env.flash`. `main.js` passes each note to both the journal and the voyage. Progress lives in `localStorage` under `paca-journal`.
- **Style:** match the existing code. Short "why" comments, no build-time tooling, plain functions returning `{ object, update, ... }`.

## Running and testing

- Serve: `python -m http.server 8417` (`.claude/launch.json` has a preview config named `paca-land`).
- **Test on an origin of your own**, such as `http://drift.localhost:8417` (the preview pane refuses `127.0.0.2` and `[::1]`), so test voyages and journal finds don't land in the owner's `localStorage`. The owner plays in the pane too, on `localhost` or `127.0.0.1`: never edit storage or reload a tab you didn't open.
- **Automated sweep.** In the page console, import `world.js` with the current `?v=` and generate many seeds. Check that nothing throws, scan geometry and `instanceMatrix` for non-finite numbers, and run `land.update()` with extreme `env` values (night + storm + flash, snow + mist, `poke: 1`). Also call every `userData.onClick` in `land.clickables`. This caught more than screenshots did.
- **Visual pass.** One seed per landmark type and biome, across clear, rain, storm, snow, mist and night. Drive time and weather through the panel (`#time` input event, `#weather-chips .chip` clicks), and check the console after each.
- **The preview pane** stalls `requestAnimationFrame` while hidden, and screenshots then drive frames. JS timers don't advance the scene, so take screenshots to let frames run. The quality watcher ignores frame gaps over 100 ms for this reason.
- **The preview pane only delivers real mouse input to the front tab.** If the owner is using the pane, test in a background tab with synthetic `PointerEvent`s, and read the target's position in the same call that dispatches (the camera auto-rotates between calls).
- **Temporary debug hooks** (`window.__x = {...}`) are fine while tuning; remove them before committing.
- **Shell patches:** bash heredocs mangle backslashes and backticks. For edits containing `\n` or template literals, use the Edit tool or write a Python patch script to the scratchpad and run it.

## How a frame works (`js/main.js`)

1. `updateSkyState()`: on the home land with no time override, `realSky(date, place)` (real sun and moon positions, phase). Otherwise `skyAtHours(hours)`: at home, the real sky at that hour today; elsewhere `syntheticSky(hours, phase)` from the land's vibe. The hours come from the slider, the time lapse or a dragged sun (`skygrab.js`, which searches `skyAtHours` for the moment that puts the sun under the pointer). For 2.6 s after a flight between lands, `glide` swings the sun and moon over from the last land's sky.
2. `sky.update(skyState, dt, t, camera)` returns the shared **`env`**: `e` (sun height), `night`, `overcast`, `rain`, `snow`, `mist`, `wet` and `snowCover` (both accumulate over time), `gloom` (lamps on), `wind`, `flash` (lightning). `land.update` adds `poke` (a tapped landmark's glow) and raises `gloom` with it.
3. `fxUniforms` (in `effects.js`) are set from `env`: time, cloud shadow, wind, wet, snow, rain, tap gusts, reflection.
4. `land.update(t, dt, env)` runs every part's updater.
5. Reflection pass (high and ultra quality, main lake only), then the composer: RenderPass → sun shafts + lens flare → bloom → OutputPass (tone mapping) → finish (tilt-shift, lens drops, vignette, warmth).

## Generating a land (`generateLand` in `js/world.js`)

Order matters, because later steps make room for earlier ones:

shape (terrain, pools, river) → top and underside meshes → landmark (with fallbacks if it doesn't fit) → path and fields → tree placement → baked AO → island mesh (painted with path and field overlays) → water and waterfall → lanterns, dock, props, light pools → trees, garden, grass, details, tufts, crystals, islets, ambient particles, mist → life (animals) → balloon → tap handlers → `patchMaterial` on every `MeshStandardMaterial` (flags: `material.userData.wind` / `.grass`).

- **Shape helpers** are pure functions of position, so everything agrees on the ground: `heightAt`, `slopeAt`, `radial`, `isWet`, `waterAt` (which pool, or the river → main lake), `shoreDistance(pool, angle)`.
- **Water:** `shape.pools`. The main `lake` is at `WATER_LEVEL`; extra ponds have their own `level`. Water triangles take their pool's level. Only the main lake mirrors (`aMirror`), because the reflection plane is a single height. Place things by `shoreDistance`, never an assumed radius.
- **Taps:** an object (or an ancestor) with `userData.onClick(hit)`, included in `land.clickables`. Instanced meshes get `hit.instanceId`; the trees map it through `flora.indexOf(hit)`. Tap sounds go through `hooks.sound(kind)`.
- **Reflections** skip `land.mirrorHide` (water, grass, details, animals, garden, bursts) to keep the second render cheap.

## Two languages (`js/i18n.js`, `js/zh.js`)

- **English is the key.** Every player-facing string goes through `t('English with {placeholders}', vars)`; `zh.js` maps that exact English to Simplified Chinese. Change a line's English and its key changes too, so rename the entry in `zh.js` in the same edit. Untranslated text shows in English and lands in `missing` (import `i18n.js` with the current `?v=` in the console).
- **Where `t()` runs:** data in `tales.js`, `voyage.js` and `lexicon.js` is translated where it's defined (the language is fixed for the page's life). Ids and anything saved stay English and are translated when shown: biome labels, weather labels, journal names, rarity reasons, quality levels, the voyage title kept in the book. Static page text is marked `data-i18n` (or is a `title`/`aria-label`/`placeholder`) and `translatePage()` swaps it at load.
- **Writing for both:** one key per whole sentence, with placeholders, rather than gluing fragments (word order differs). Plurals get separate keys (`1 mile` / `{n} miles`). Use curly quotes (’ “ ”) in English, never a straight `'` inside `t('…')`. `aLetter()` says "an N" in English and just "N" in Chinese. `el()` in `voyage.js` drops the spaces English puts between sentences when the text is Chinese.
- **Chinese conventions:** Wa keeps her Latin name (typing "wa" is a riddle answer), the Hush is 寂静, the Edge of the Sky is 天边, a mile is 里, and the words you type, riddle letters and island names stay English. Write it as a Chinese storybook would, not word for word (an early pass had calques like 短促的呼吸 for "short breath", now 气短).
- **Check coverage** with `python .claude/i18n-keys.py --check`: it scans the source for `t('…')` literals plus the data translated at display, diffs them against `zh.js` keys, and checks every translation keeps its `{placeholders}`. Then run the bot in both languages and scan everything it saw for `undefined`, `{` and stray English.
- **Switching** saves `paca-lang` and reloads (strings are read at load). If a voyage is under way, a `sessionStorage` flag makes `main.js` call `voyage.pickUp()` instead of visiting the address-bar land.

## Drift (`js/lexicon.js`, `js/voyage.js`, `js/tales.js`)

The voyage game. `lexicon.js` is pure: `MEANINGS` (words and 4+ letter roots, each with an `effect`), `RULES` (form rules), `SECRETS`, `WIND_WORDS`, and `readWord(raw, { used, last })`, which returns leagues, fuel, meanings, the merged effect and the rules a word triggers. `voyage.js` is the game: state, cards, the HUD, the book. It talks to `main.js` only through the `api` it's given (`fly`, `leave`, `setClock`, `clearStorm`, `toast`) and the hooks `main.js` calls (`landOptions`, `vibe`, `arrived`, `note`, `tapped`, `preview`, `submit`, `update`). `tales.js` is data: `STORY` (Wa, the player's grandmother: the intro, her pages, the ending) and `WA_NOTES`, `REACHES`, `GATES` and `RIDDLES`, `OMENS`, `KEEPSAKES`, `CREW`, `DARES`, `HUSH` and `SKY_EVENTS`. Tales act through `g`, made by `talesView()` in `voyage.js` (`give`, `hurt`, `keepsake`, `board`, `leagues`, `hours`, `flag`/`mark`, …); each helper returns a few words saying what happened, for the outcome card.

- **Distances are miles on screen and `leagues` in code** (`run.leagues`, `reading.leagues`, `g.leagues()`): only the words changed. A hop is `hopOf(reading)` in `voyage.js`: the word's letters (plus fast words and "faraway"), then `PLACE_MILES` by meaning, `AIR_MILES` by the biome you leave from, storm winds, and a gust seeded by island and word, so the preview and the flight always agree. Keep the extras centred near zero, or voyages get shorter or longer for everyone.
- **Real words only where a word is asked for.** `readWord` sets `reading.real` from `isWord()` in `lexicon.js`: the dwyl list in `vendor/words` (trimmed to 2–14 letters, fetched by `loadWords()` when a voyage starts), plus Drift's own words and `EXTRA_WORDS` (modern words the list lacks). Only gates (`answers`), the pirates' dare (`dareMet`) and the queen's quest check it; any other word still flies, and its island is made up. Until the list loads, or if it can't, every word counts. In a console test, `await loadWords()` first.
- **The alpha password.** Drift is in alpha for family: starting a first voyage asks for `PASSWORD` (`'family'`, in `voyage.js`, deliberately in plain sight), case-insensitive, then remembers it in `localStorage` as `paca-alpha`. A voyage already under way resumes without asking. Bots and test tabs need `localStorage.setItem('paca-alpha', 'true')` first. To open Drift to everyone, make `intro()` skip `askPassword()`.
- **Voyage lands use the seed `~word`.** `voyage.landOptions(seed)` returns overrides (`biome`, `landmark`, `lake`, `river`, `balloon`) for `generateLand(seed, want)`, and `voyage.vibe(seed, land)` replaces the land's seeded hour, moon and weather. Both return nothing for other seeds.
- **The owner's admin link** (`#!…`, `adminLand()` in `main.js`) grows any island with any features: `#!ember/castle/lake/falls/balloon/storm/23/kettle` (any order; `none` = no landmark, `dry` = no water; hours as 0–23 or `dawn`/`noon`/`golden`/`night`…; the last unrecognised part is the word grown, the home land if there's none). `#!` alone shows the syntax. It starts with "!" so no island name can clash (it was `#patrick`, which is also someone's island). It passes `want` to `generateLand` like a voyage does, sets the weather and time overrides, and skips rarity and the journal. Not advertised in the README, like the alpha password.
- **Overrides must not change free-mode lands.** `generateLand` and `makeShape` roll every die first (`rolledBiome`, `rolledLandmark`, `rollLake`, `rollRiver`, `rollBalloon`) and apply `want` after, so the draw sequence is the same with or without overrides. Keep it that way, and check a few seeds against `HEAD` after touching generation.
- **Voyage lands skip rarity:** no tier in the meta line, no rarity toasts, no legendary count or best-find in the journal (`journal.visit(..., onVoyage)`). Overrides make lands look rarer than they are. Voyage finds are saved with `voyage: true` and aren't links.
- **On a voyage** time is part of the game: `skyGrab` is disabled, the dice, panel, share, tweak and hint are hidden (`body.voyaging`), the book button opens the language book, and `hashchange` is ignored.
- **The journal lists voyage islands too** (its `voyage islands` section, `VOYAGE_ONLY` in `journal.js`): found only on voyages, filled in at load from Wa's book (`paca-language` islands) for islands reached before the section existed, and left out of the naturalist badge, since Drift is behind the password.
- **Voyage-only islands** (`mire`, `coral`, `toadstool`, `stormcrag`, `glass`, `ember`, `gilded`, `jungle`, `savanna`, `heath`, `lavender`, `cloudisle`, `withered`, `sugar`, `bamboo`, `terraces`, `clockwork`, `paper`, `moon`, `maze`, `giant` in `BIOMES`) have `weight: 0`, and the free-mode roll filters them out before drawing, so ordinary lands and the rarity tables are untouched. Lava is `water.lava`: it glows (`uLava` in the water shader, `uGlow`/`uFoam` in the falls, both zero for other water), never freezes, and has no fish, ducks, dock or lily pads.
- **Saved runs are data only.** Anything that must survive a reload (a dare, a flag, the treasure word) goes in `run` as plain values; behaviour stays in `tales.js`, looked up by id. Old saves are merged over `newRun()`, so a new field needs a sensible default there (and gates behind an old save count as passed).
- **Lessons from the playtests** (both languages, October): a drift is never turned back by a gate (the wind carries you up to it, no heart lost, and you reach a new island with fresh hours); nearly out of fuel (under 3), any tree also gives a few dry twigs (+1 🔥); a tap whose stores are all full costs no hour; sleeping at the cabin lasts until 7:00 (`sleepHours()`, at least an hour); waiting out a storm works even after your hours are spent; the queen never asks for a letter you've already brought her (`run.flags.quests`); and every gamble's note names its stakes. From the second round (October 18): a building's offer that would only fill full stores says so and costs no hour (`wasted()` in `voyage.js`); story text never says “tonight” or a weather (a chapter can come at any hour, in any sky); a character never shares a name a player might sign (the campsite girl was Juniper until a tester signed as Juniper); a story's facts must agree across chapters and islands (where Rowan is, what happened to Wa's jar); a reward in a sad moment gets a reason (“for listening”); and a misheard word still opens a gate, with a line saying the gate knew what you meant.
- **Tales must not strand a voyage.** Every card has an enabled way out, a gate or the Hush can always be answered (the Hush's "tear free" is never disabled), and drifting is offered whenever the cheapest word is out of reach.
- **Storage:** `paca-voyage` holds the voyage in progress (saved after every change, cleared on win or loss). `paca-language` is the book: meanings, rules, secrets, islands, keepsakes, passengers and omens met, and the last 12 voyages.
- **Balance knobs** sit at the top of `voyage.js` (`GOAL`, `STAY`, `START`, `MAX`, `TREES`, `SKY_EVENT_CHANCE`), in `HUSH` and `OMENS` in `tales.js`, and in each landmark's event. A voyage should take 20 to 30 minutes, about 15 lands. To test an ending, edit `paca-voyage` in the console (say `leagues: 95`) and reload.
- **Each island's own life.** `TREE_SPECIES` in `world.js` gives every biome a weighted mix of tree kinds (`speciesGeometry`/`speciesColors` build them; `CROWN_TOP` says where snow and blossom sit). It's one draw per tree, so changing a mix changes which trees grow but not where. `CRITTERS` and `NEIGHBOURS` in `life.js` add each biome's wandering animals from their own `fauna` stream, so adding one leaves the older animals where they were. Each new kind needs a `THANKS` line in `voyage.js` (a coin the first time you meet it), a journal entry (`life:kind`, with voyage-only ones under "voyage wildlife") and a `TREES` yield in `voyage.js` for a new biome.
- **Who you are.** The first `begin()` asks for a name (`signLogbook()`), saved as `book.name` with `book.named`; an empty name means Sparrow (`STORY.sparrow`), what Wa called you. Text gets it through `you()` in `voyage.js` and `g.name`/`g.signed` in tales and stories. The story's turn: the Hush is made of words nobody said, and the one following Wa is the thing she never said to your mother (she left after a falling-out). So in Chinese she's 外婆 (your mother's mother), and her husband 外公.
- **Building stories** (`js/stories.js`): `ARCS[landmark]` is three chapters, each `{ ask, tell(g) }` returning a card like a sky event's. A building's card gets the next chapter as its first option, once per island (`run.flags.storied`); progress is `book.arcs[id] = { ch, picks, done }`, so a story runs across voyages and later chapters can read earlier choices or other stories (`g.arcDone('windmill')`). A finished story is a perk for good: `friend(book, id)` in `EVENTS` (cheaper market, a second lantern, the ruins never hurt…), named by the arc's `perk` line on the last outcome card.
- **Balance with a bot.** `.claude/drift-bot.js` does this: on an origin of your own, set `paca-alpha` and `paca-lang`, reload, `await import('/.claude/drift-bot.js?' + Date.now())`, then `await __bot(n, { landmark, story })` and `__scan()` (broken or untranslated text, errors, story progress, wins). It plays like a careful player: gate answers first, short words otherwise, trees and water every land. A bot that taps animals instead of trees starves, which looks like a balance bug and isn't. To compare against what's deployed, `git archive HEAD | tar -x -C <dir>` and serve that on another port with the same bot. In October 2026 it won about 40–50% of voyages in ~18 lands, the same before and after the new islands and stories. Under the hood it's `createVoyage` with a fake `api` (`fly` queues the seed; the bot then calls `landOptions`, `vibe` and `arrived` with a made-up land) can play hundreds of voyages in a minute, clicking cards and submitting words through the instance's own DOM. A naive bot won about half its voyages in ~15 lands, with the Hush catching it about once every two voyages; re-run it after changing numbers, and watch per-omen win rates.
- **Playtest for clarity, not just balance.** The bot can't tell if text makes sense. Give a fresh agent (told nothing about the rules) a text-only harness in its own tab, on a fresh origin like `http://play-en.localhost:8417` so its book starts empty. `.claude/drift-play.js` is that harness (paste it into the page after setting `paca-alpha` and `paca-lang`): a second `createVoyage` with a fake `api`, wrapped as `window.__play` (`start`, `look`, `choose`, `write` for the logbook's name box, `preview`, `fly`, `tap`, `book`, `chip`), with `look()` returning the card, options and notes, the text box, the status line, the gauges with their hover text, and toasts. Have it play full voyages and then read `tales.js`, `lexicon.js` and the strings in `voyage.js`, and report confusing, unexplained or overwritten text with quotes and rewrites. The first run found a dozen real problems (full stores failing silently, offers re-rolling every hour, terms used before they're explained).
- **The preview keeps the sky's secrets:** `heardOf` names only kinds of words already in the book; anything else is "something you haven't learned yet". Fatal-flight warnings and passenger hints follow the same rule, so they don't leak a meaning.
- **Wa's story state** lives in the book: `book.found` (you've reached the Edge once: the intro, harbor, Hush card and ending change, and her pages stop turning up) and `book.pages` (pages kept, shown in the book; `camp` holds the word her camp page taught). The Edge's riddle is always `wa` (one of her words, `SECRETS`), and her camp in the Thin Air teaches one you haven't said.
- **Voyage islands are named after the word** the sky heard (`main.js`, `arrive`), with the kind of island under it.
- **The currency is coins (🪙)**, stored as `glimmer` in `run` and the book (old saves keep working).
- **House style for game text:** plain and concrete. Name things before using them, say what a cost or reward actually is (−1 ❤️, not "they cut a rope"), and give examples of a kind of word ("wind words (breeze, gust…)"). Lowercase titles and labels.

## Traps already hit (don't repeat)

- **Never multiply absolute time by a changing speed** (`sin(t * speed)` with a varying `speed`): the phase jumps and things shake wildly (the castle flags). Accumulate a phase with `dt` instead.
- **Obstacle avoidance that turns every frame makes things spin** (the deer). Check obstacles only while moving, turn once, add a cooldown, and turn smoothly toward an aim.
- **GLSL `pow()` with a possibly-negative base gives NaN**, which bloom spreads into black blocks. Clamp bases (`max(1.0 - x, 0.0)`), and use `x * x` for squares.
- three r170: `InstancedMesh.getColorAt(i, color)` fills `color` and returns nothing.
- `THREE.MathUtils.smoothstep(x, min, max)` needs `min < max`. The local `smoothstep(e0, e1, x)` helpers in each module accept reversed edges, which is how fades are written here.
- The Euler order is XYZ. For "tilt, then turn" (ferns, rails), rotate the geometry first, then place it with `ry`.
- A hidden tab can report a 0×0 viewport. `resize()` bails out, because sizing to 0×0 made the camera position NaN for good.
- **Weather and time picks are per land:** `visit()` resets the overrides, or a "snow" pick buried the next land in snow.
- **OrbitControls' `zoomToCursor` moves the orbit target with every zoom.** `keepNearHome()` in `main.js` pulls it back toward the land's middle as the camera backs out (not in photo mode, not during a double-click glide), or the land ends up circling a point in mid-air.
- **Touch double-taps** are detected in `interact.js`; the browser's own `dblclick` is ignored for touch so a double-tap doesn't zoom twice.
- **Input that must win over OrbitControls** (grabbing the sun) listens for `pointerdown` in the capture phase on `window` and stops it there. Listeners on the canvas itself run too late.
- Every light added to the scene changes the shader defines and recompiles every material. Landmarks carry a `PointLight`, so keep lights out of anything that comes and goes.
- PCSS shadows patch `ShaderChunk.shadowmap_pars_fragment` and must run before any material compiles (desktop only; `?pcss=0` disables them).
- Night readability is deliberate "day for night" (lifted blue skylight, stronger moon, exposure). Realistic-dark nights looked black.

## Performance notes

- Generating a land takes ~100–160 ms (grass sampling, AO baking, pool noise in `heightAt`). Trimming it is an open item.
- An RTX 5070 Ti laptop holds 120 fps at ultra. The watcher steps down below 30 fps and steps back up when smooth, with a ceiling against bouncing between levels.
